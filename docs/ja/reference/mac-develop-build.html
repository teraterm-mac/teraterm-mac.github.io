ビルド・テスト・リリース (Mac 版)

必要なもの

  • Mac と、Xcode またはそのコマンドラインツール (Swift 5.5 以上。Package.swift は swift-tools-version 5.5)
  • できたアプリは macOS 11 以上で動きます (Package.swift の platforms と、Info.plist の LSMinimumSystemVersion が 11.0)。
  • macOS 11 で動くように、Sparkle は 2.9 系にしています (2.10 からは macOS 12 以上)。また、SDK に NS_SWIFT_SENDABLE がないときのために、TeraMac ターゲットでは空の定義を渡しています (注釈だけなので動きは変わりません)。
  • リポジトリ全体 (macos/ の外の本家のファイルも) が必要です。scripts/bundle.sh は ../installer/release と ../teraterm/common/helpid.h を読みます。

ビルドと実行

コマンドはどれも macos/ で実行します。

cd macos
swift build                        # デバッグビルド (.build/debug/TeraMac)
./scripts/bundle.sh                # "build/Tera Term Mac.app" を作る (この Mac 用。速い)
open "build/Tera Term Mac.app"
./scripts/bundle.sh --universal    # Apple Silicon と Intel の両対応
./scripts/bundle.sh --dmg          # 両対応でビルドし、配布用の DMG を作って公証まで行う

swift build だけで動かしたときは、画面の言語とヘルプはソースのフォルダ (macos/Resources と本家の installer/release/lang_utf8) から読みます。自動アップデートは、Info.plist に SUFeedURL があるとき (bundle.sh で作ったアプリ) だけ動きます。

bundle.sh がすること

  1. swift build -c release (--universal / --dmg では --arch arm64 --arch x86_64) でビルドし、実行ファイルを strip -x で小さくします。
  2. build/Tera Term Mac.app を作り、次のものを入れます。
    • Sparkle.framework (ヘッダーと XPC サービスは外す)
    • アイコン (Resources/AppIcon.icns) と LICENSE
    • 本家の installer/release/TERATERM.INI (設定の初期値)
    • 本家の installer/release/lang_utf8/*.lng と Resources/lang/mac_*.lng (画面の言語)
    • 本家の installer/release/theme (テーマの見本)
    • Resources/help-mac/{ja,en} のヘルプ (html/、teraterm.hhp、modern-toc.json) と本家の teraterm/common/helpid.h。画像 (*.png) は入れません (ヘルプの画像)
  3. Info.plist を書きます。版は bundle.sh の VERSION (環境変数 VERSION でも変えられます)、バンドル ID は BUNDLE_ID で変えられます。.ttl ファイルの関連付けと Sparkle の設定 (SUFeedURL、公開鍵など) もここに入ります。
  4. 署名します。キーチェーンに「Developer ID Application」の証明書があればそれで (Sparkle の中身から順に、hardened runtime とタイムスタンプ付き)、なければ ad-hoc 署名です。環境変数 SIGN_ID で使う証明書を指定できます。
  5. --dmg のときは、アプリと「アプリケーション」へのリンクを入れた DMG (build/TeraTermMac-<版>.dmg) を作ります。背景は scripts/make_dmg_bg.swift で描き、Finder で窓の大きさとアイコンの位置を設定します。
  6. Developer ID で署名したときは DMG も署名し、xcrun notarytool で公証して stapler で公証の結果を付けます。notarytool の資格情報は、あらかじめ xcrun notarytool store-credentials でキーチェーンに保存しておき、そのプロファイル名を環境変数 NOTARY_PROFILE で渡します。保存した資格情報がないときや SKIP_NOTARY=1 のときは公証をとばします。

テスト

swift test                                  # すべてのテスト
swift test --filter TTLTests                # 1 つのテストクラスだけ
swift test --filter TerminalTests/testXxx   # 1 つのテストだけ

テストは Tests/TeraCoreTests にあり、TeraCore (端末エミュレータ、TTL マクロ、ファイル転送、TEK、キーマップ、INI ファイル、接続の設定など) を対象にしています。

  • TTLUpstreamTests: 本家の tests/*.ttl を画面なしでまとめて動かし、どの行でどんなエラーになったかを一覧にします。対話や接続が要るものが多いので、環境変数 TERAMAC_UPSTREAM_REPORT に結果のファイルを指定したときだけ動きます。 
    TERAMAC_UPSTREAM_REPORT=結果.txt swift test --filter TTLUpstreamTests
  • TTLBenchTests: マクロの速さを測ります。デバッグビルドではとばすので、リリースビルドで動かします。 
    swift build -c release -Xswiftc -enable-testing --build-tests

自己テスト用の環境変数

アプリの実行ファイル ("build/Tera Term Mac.app/Contents/MacOS/TeraMac") に環境変数を付けて起動すると、見た目や動きを確かめるための動きをします。

環境変数動き
TERAMAC_SNAPSHOT=<フォルダ>画面・ダイアログを PNG に書き出して終わります (term.png、about.png、credits.png、connect.png、setup.png、schemes.png、menu_editor.png、menu_details.png など)。途中でマクロ (test.ttl) を動かしてローカルシェルにつなぎ、画面の文字を shell.txt に書きます。TeraTerm Menu の画面は見本の接続先で写し、終わったら登録内容を元に戻します。自動アップデートとアプリケーションフォルダへの移動の案内は出しません
TERAMAC_TCPPORT=<ポート>TERAMAC_SNAPSHOT のマクロで、127.0.0.1 のそのポートに生の TCP でつなぎ、送った文字が返ってくるか確かめます (相手はエコーするサーバーを用意します)
TERAMAC_SERIAL=<デバイス>TERAMAC_SNAPSHOT のマクロで、そのシリアルポートに 115200bps でつなぎ、serial-ping を送って serial-pong を待ちます
TERAMAC_LOGINPORT=<ポート>TERAMAC_SNAPSHOT で、TeraTerm Menu の自動ログイン (127.0.0.1 のそのポートに /T=0 で接続) を実際に動かし、画面の文字を menu_login.txt に書きます
TERAMAC_TABSNAP=1TERAMAC_SNAPSHOT と一緒に使います。タブを 2 つにしてウインドウ全体を写し (tabs.png)、設定のシート、フォントを変えたときのその場の反映、キャンセルで戻るかを写します
TERAMAC_SETUP_SNAPSHOT=<フォルダ>その他の設定のシートを開いたとき、すべてのタブを setup-<番号>-<名前>.png に書き、TTSSH / TTProxy のダイアログも写します
TERAMAC_DEBUG_WINDOWS=<ファイル>起動して 2 秒後に、見えているウインドウ (クラス・題・大きさ) とアプリのメニューの項目をファイルに書きます
TERAMAC_MENUBAR_TEST=<ログ>ウインドウの中のメニューバーを開いてマウスを隣の題へ動かし、メニューが切り替わるかをログに書きます
TERAMAC_INI_DRYRUN=<ini>TERATERM.INI を読み込んだ結果 (反映する設定・しない設定・ホストの一覧・フォントなど) を書き出して終わります。設定は変えません。書き出し先は TERAMAC_INI_OUT (既定は標準出力)
TERAMAC_TTMENU_TEST=<ttpmenu.ini>ttpmenu.ini を読んで書き出し (<ini>.written.ini)、もう一度読んだ結果を <ini>.out.txt に書いて終わります。保存はしません
TERAMAC_FEED_URL=<URL>自動アップデートが見に行く appcast.xml を変えます (file:// も使えます)
TERAMAC_UPDATE_TEST=<ログ>画面を出さずに、アップデートの確認 → ダウンロード → 入れ替えまで行い、経過をログに書きます

このほか、TERAMAC_PROXY_* はプロキシを使うときにアプリが ssh の ProxyCommand (TeraMac --proxy-connect <ホスト> <ポート>) に設定を渡すための環境変数です。--purge-keychain はアンインストーラーが使う引数で、保存したパスワードを消して終わります。

生成スクリプト

スクリプト作るもの
scripts/gen_charwidth_tables.py本家の teraterm/teraterm の unicode_asian_width.tbl・unicode_combine.tbl・unicode_emoji.tbl から Sources/TeraCore/CharWidthTables.swift を作ります。
python3 scripts/gen_charwidth_tables.py [teraterm/teraterm のフォルダ]
scripts/gen_sbcs_tables.py本家の teraterm/teraterm/mapping/*.map から Sources/TeraCore/SBCSTables.swift を作ります。
python3 scripts/gen_sbcs_tables.py [mapping のフォルダ]
scripts/notes2html.pyリリースノート (GitHub Releases と同じ Markdown) を、更新の画面 (Sparkle) に出す HTML にします。使えるのは段落・見出し・箇条書き・コード・太字・リンクだけです。appcast.sh が呼びます。
python3 scripts/notes2html.py notes.md > notes.html
scripts/make_icon.swift本家のアイコン (teraterm/common/teraterm.ico) から AppIcon.iconset を作ります
scripts/make_dmg_bg.swiftDMG の背景の絵を描きます (bundle.sh が呼びます)

生成された .swift ファイルは手で直さず、スクリプトを動かし直してください。

リリースの手順

  1. scripts/bundle.sh の VERSION を上げます。
  2. ./scripts/bundle.sh --dmg で DMG を作ります (署名・公証まで)。
  3. GitHub Releases に v<版> を作り、TeraTermMac-<版>.dmg を上げます。
  4. ./scripts/appcast.sh <版> build/TeraTermMac-<版>.dmg [リリースノート.md] で macos/appcast.xml を書き直し、main に push します。アプリはこの appcast.xml (Info.plist の SUFeedURL) を見て新しい版に気づきます。

appcast.sh は Sparkle の sign_update (既定は tools/sparkle/sign_update。Sparkle のリリースの bin/ から置きます。環境変数 SIGN_UPDATE で変えられます) で、DMG に EdDSA (ed25519) の署名をします。秘密鍵はキーチェーンではなく鍵ファイルから読み、場所は環境変数 SPARKLE_KEY で指定できます。この鍵の公開鍵が Info.plist の SUPublicEDKey に入っているので、鍵をなくすと今のアプリに更新を届けられなくなります。安全な場所にバックアップしておいてください。

appcast.xml には最新の版 1 つだけを書きます。リリースノートを渡すと、更新の画面に「更新内容」として出ます (.md は notes2html.py で HTML にします。.html はそのまま使います)。
