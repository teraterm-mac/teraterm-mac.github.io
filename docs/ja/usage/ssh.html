SSH 接続

Tera Term Mac の SSH 接続について解説します。Tera Term Mac は macOS に入っている OpenSSH の ssh コマンド (/usr/bin/ssh) を使って、SSH2 プロトコルで接続します。SSH の設定は、できるかぎり ssh のオプションに直して渡します。

前提知識

SSH の認証方式には

  • パスワード認証
  • 公開鍵（と秘密鍵のペアによる）認証
    • 認証エージェントを利用する (macOS の ssh-agent を使います)
  • keyboard-interactive 認証

があります。ここでは需要が多いと思われる認証方法について触れたいと思います。

接続の手順

[ファイル] メニューの「新しい接続...」(⌘N) を選ぶと、接続ダイアログが開きます。 「ホスト」に接続先を入れ、「サービス」で SSH を選んで「接続」を押します。

認証は接続ダイアログの内容と、ssh コマンドのやりとりで行います。
どの認証方式を先に試すかは [設定] メニューの「SSH認証...」で設定できます (ssh の PreferredAuthentications として渡します)。 ssh はひとつの認証方式に失敗すると、サーバが許している次の方式を続けて試します。

  • パスワード認証を使用する場合は、「ユーザー名」と「パスワード」を入力します。「パスワード」を空にすると、ssh が端末にパスワードを聞いてくるので、そこで入力します。パスワードを入れておくと、パスワードの入力を求められたときに Tera Term Mac が自動で送ります。
    ※パスワード送信時の SSH パケットは暗号化されているので、TELNET のようにパスワードが平文で送信されることはありません。
  • 公開鍵認証を用いる場合は、「秘密鍵」の「選ぶ…」ボタンで秘密鍵のファイルを指定します (ssh の -i)。空のときは ~/.ssh にある鍵など、ssh の標準の鍵を使います。パスフレーズは端末で聞かれます。
    ※使える秘密鍵の形式は OpenSSH が読めるものだけです。PuTTY 形式 (.ppk) の鍵は、PuTTYgen などで OpenSSH 形式に変換してください。
  • keyboard-interactive 認証では、サーバからのプロンプトが端末に表示されるので、そこで入力します。
  • 認証エージェントを用いる場合は、ssh-agent に鍵を登録しておきます (ssh-add)。macOS では、パスフレーズをキーチェーンに保存しておくこともできます (ssh-add --apple-use-keychain)。

ユーザ名入力

接続ダイアログには、設定によってあらかじめユーザ名が入力されます。 「ログオンユーザ名を使用」を選ぶと、この Mac にログインしているユーザ名が入ります。

漢字などの非ASCII文字を入力できます(RFC 4252)。サーバーも対応している必要があります。
参照: ユーザ名またはパスワードに非 ASCII 文字を使用する場合の注意

パスワード / パスフレーズ入力

ssh が端末でパスワードやパスフレーズを聞いてきたときは、そのまま端末に入力します。入力した文字は表示されません。

  • ⌘V で貼り付けることもできます。

セキュリティ警告

ssh_known_hosts ファイル

SSH 接続時には、ssh がサーバのホスト鍵を known_hosts ファイルと照らし合わせます。既定は ~/.ssh/known_hosts で、macOS のターミナルで ssh を使うときと同じファイルです。ファイルは [設定] メニューの「SSH...」で変えられます。
結果によって、ssh は端末に次のように表示します。

  • 接続中のホストの鍵が登録されていない: 「The authenticity of host ... can't be established.」と指紋が表示され、続けるか聞かれます。yes と入力すると鍵を登録して接続します。
  • 登録されている鍵と違う: 「REMOTE HOST IDENTIFICATION HAS CHANGED!」と表示され、接続しません。
  • 登録されている鍵と同じ: 警告は表示されません。

警告が表示された場合には、意図しないサーバに接続しているか中間者攻撃に遭っている可能性があります。
しかし、始めてサーバに接続するときや、サーバの再インストールなどにより SSH サーバのホスト鍵が変更された場合にもこの警告が表示されます。「警告に表示されている、接続中の SSH サーバのホスト鍵の指紋」と「接続しようとしている SSH サーバのホスト鍵の正確な指紋」を比較してください。
ホスト鍵が正しく変わったことを確かめたら、ローカルシェル (⌘G) で ssh-keygen -R ホスト名 を実行して古い鍵を消し、接続し直します。

OpenSSH の場合、サーバ管理者は以下のようなコマンドでサーバのホスト鍵の指紋を取得できます。

ssh-keygen -l -f /etc/ssh/ssh_host_rsa_key.pub

SSHFP RR

SSH 接続時に、RFC 4255 に規定されている SSHFP RR (Secure SHell FingerPrint Resource Record) による検証が可能です。[設定] メニューの「SSH...」の設定を、ssh の VerifyHostKeyDNS オプションとして渡します。

ドメインの所有者であれば DNS の SSHFP レコードに SSH サーバホスト鍵の指紋を登録することが可能です。ssh は SSHFP レコードを取得し、接続中のサーバホスト鍵と比較します。

SSHFP に関して規定している RFC 4255 には「DNSSEC 認証されていない SSHFP RR を信頼してはならない」とあります。DNSSEC で検証できないときは、ssh は一致したことを表示するだけで、known_hosts にない鍵はこれまでどおり確認を求めます。

キーの生成

ここで、公開鍵認証に用いる公開鍵・秘密鍵ペアの生成方法を説明します。鍵ファイルを生成するには [設定] メニューから「SSH鍵生成...」を選択します。鍵は macOS の ssh-keygen コマンドで作ります。

「鍵の種類」で RSA、DSA、ECDSA-256/384/521、ED25519 から選べます。鍵のパスフレーズ（パスワードのようなもの。ただし空白を含んでもいいし、一般にパスワードよりも長い物が指定可能）とコメントを入力して「生成」を押します。その後、「公開鍵の保存」ボタン、「秘密鍵の保存」ボタンを押してキーを保存します。保存先は ~/.ssh フォルダが一般的です。保存が終わったら「閉じる」で終了します。

このキー・ファイルの使用方法ですが、拡張子が「pub」となっているファイル（「公開鍵」）の内容を、サーバの指定の場所に保管します。（一般的には (home dir)/.ssh/authorized_keys に内容を追加します。ローカルシェルで ssh-copy-id コマンドを使うこともできます。）また、拡張子が付いていないファイルは「秘密鍵」となり、ログイン時に指定する事となります。

注意：秘密鍵（private key）は第三者に絶対に知られてはいけないため、管理を厳重に行うようにしてください。また、誤ってサーバへ転送してしまわないようにしてください。
